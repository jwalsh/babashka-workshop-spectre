#+TITLE: Babashka Workshop - Spectre

Build a password manager with Babashka:

- The stateless [[https://spectre.app/][Spectre password algorithm]]. See the [[https://spectre.app/spectre-algorithm.pdf][algorithm description]].
- Local storage for site settings, with a terminal UI for editing them.
- A command-line interface for generating passwords.
- Babashka extensions for native scrypt implementations.

* Prerequisites

Install the following:

- [[https://github.com/babashka/babashka#installation][Babashka]], with FFI support if you want to use the libsodium implementation (>= 1.13.220, latest recommended).
  - Set up zsh completions with:
    ~source <(bb org.babashka.cli/completions snippet --shell zsh --prog bb)~.
    See https://github.com/babashka/cli#completions for other shells.
- Java 17 or later. FFI requires Java 22 or later.
- [[https://clojure.org/guides/install_clojure][Clojure CLI]] (optional).
- [[https://github.com/babashka/bbin#installation][bbin]] for E6.
- OpenSSL 3 or later, unless you use the FFI implementation.
- [[https://libsodium.gitbook.io/doc/installation][libsodium]] for the FFI implementation

On macOS, install OpenSSL with ~brew install openssl~. The system OpenSSL version is not compatible.

On Windows 10 or later, install OpenSSL with ~winget install openssl~.

** Editor setup

For editor support, install:

- Clojure [[https://clojure-lsp.io/installation/][LSP]]
- A structural editing mode such as Paredit or Parinfer.

- VSCode/Codium: https://calva.io/

* Working in this checkout

Everything from here to the license is local to this fork: tooling for working through the workshop, not part of it. The workshop's code is ~src/~ and ~test/~, and ~bb.edn~ is untouched.

** The method

REPL first. Read a namespace, load it, read the docs for the calls it uses, and try them from the file's ~(comment ...)~ block. The test, or the stub, comes after that, and says what the exploration already showed.

So the tooling is about seeing: what a namespace loads, who calls a stub, what a library call returns, what the editor and the REPL are doing right now. [[file:exercises.org][exercises.org]] carries that for each exercise under /Working it here/, and how to look up documentation for the ~babashka.fs~ and ~babashka.process~ calls the stubs name.

** Start

#+begin_src sh :eval no
gmake deps          # what the workshop needs, and what is installed
gmake .env          # the throwaway identity the tests use; never overwrites
direnv allow        # this checkout's own db.edn, nREPL port and bbin directory
gmake demo          # Emacs in a frame, jacked in to babashka, core.clj loaded
gmake status        # is the REPL live, and is it this checkout's
#+end_src

~gmake session~ is ~gmake demo~ inside a detached tmux session, which an agent can read with ~gmake session-shot~. Either way ~brepl -e '(form)'~ evaluates in the same REPL from a shell.

** Emacs

[[file:babashka-workshop-spectre.el][babashka-workshop-spectre.el]] is the wiring, and its commentary lists the commands. ~gmake demo~ and ~gmake session~ load it. It jacks CIDER in to babashka, puts clj-kondo's findings in the buffer through Flymake, makes ~C-c C-c~ inside a ~comment~ block evaluate one form, shows keystrokes in the header line when keycast is installed, and keeps a log of every nREPL message. ~M-x spectre-test-ns~ runs the tests for the buffer's namespace.

** For an agent

~.claude/settings.json~ has two hooks: the session status is put in context at start, and every Write and Edit of a Clojure file has its delimiters balanced and is formatted with cljfmt. ~dev/claude-plugins/~ is a local plugin that puts ~clojure-lsp~ behind Claude Code's LSP tool. [[file:AGENTS.md][AGENTS.md]] is the contract.

** Checkouts

~main~ carries the tooling. Exercises are worked on branches in ~worktrees/~, each with its own ~db.edn~, nREPL port, bbin directory and tmux session, derived in ~.envrc~. A new worktree needs ~gmake .env~ and ~direnv allow~ once.
